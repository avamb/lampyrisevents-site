# Скорость: WordPress (lampyrisevents.com) vs новый статический сайт (new.lampyrisevents.com)

Замер: 22.11.2026 23:05 – 23.11.2026 ~02:00 по Мадриду (Lighthouse 23:05–01:35, затем TTFB). Сайты только читались.

## Сводка

- **mobile**: Performance в среднем 42 → 73; LCP 12.4 → 1.9 с; TBT 1467 → 7055 мс; вес 3597 → 1020 КБ; запросов 132 → 30.
- **desktop**: Performance в среднем 64 → 87; LCP 5.7 → 0.7 с; TBT 148 → 3010 мс; вес 3556 → 1054 КБ; запросов 134 → 31.
- **TTFB** (тёплый, среднее по 10 страницам): 1104 → 187 мс.
- Новый сайт — статика за Cloudflare (br, Cache-Control 300 с); старый — PHP 8.3 на WordPress, `cf-cache-status: DYNAMIC`, страницы не кэшируются на CDN.
- Старый сайт нестабилен под Lighthouse: 16 из 120 запусков (15 на старом) упали с «page did not paint»/таймаутом и были перезапущены; одна комбинация (отмечена *, `/ru/tours/` desktop, старый) так и дала только 2 прогона.
- **Важная оговорка по TBT нового сайта.** На главных, турах и мероприятиях TBT ≈ 9–10 с и score 64–70 — это один длинный таск 10 с в скрипте Meta Pixel (`connect.facebook.net/signals/config/…`), он сработал в 2 из 3 прогонов на главной (в 3-м TBT 0,5 с, score 87). Вероятно, артефакт headless-Chrome + пикселя, но проверить это на реальном устройстве стоит; без пикселя страницы остаются на 98–100 (см. desktop `/about-us/`, `/past-events/`). Медиана честно показывает это как есть.
- Вес новой страницы в 2–10 раз меньше (кроме страниц мероприятий с виджетом: 1,7–2,4 МБ); LCP/FCP/SI лучше во всех 10 парах, TTFB ~1,1 с против ~0,2 с.
- Оговорка: в «тёплом/холодном» TTFB разницы у старого сайта нет, потому что кэш WordPress/CDN не работает ни в каком режиме; у нового «холодный» чуть выше только из-за нового соединения/кэша Cloudflare.

## Условия замера

- Lighthouse 12.8.2 (npm), Chrome для Windows 11 headless, только категория Performance; mobile — стандартный симулированный троттлинг (Slow 4G, CPU ×4), desktop — preset desktop. Каждая страница × сайт × режим по 3 запуска, запуски чередовались старый/новый, последовательно; в таблице медиана.
- Откуда: домашний/офисный компьютер владельца (Windows 11), канал и регион не уточнялись; абсолютные цифры зависят от канала, сравнение — на одной машине.
- User-Agent: обычный Chrome 130 (со стандартным curl UA старый сайт отдаёт страницу «Blocked»).
- TTFB: curl `time_starttransfer`. «Холодный» = запрос с уникальным `?cb=…` (обход кэша страницы), медиана из 3; «тёплый» = тот же URL после двух прогревающих запросов, медиана из 5.
- Вес = `total-byte-weight` Lighthouse (сжатый, по сети); запросов = число сетевых запросов за загрузку. На новом сайте уже подключены GA и Meta Pixel (они входят в вес и TBT).
- Сырые JSON-отчёты не в репозитории (scratchpad).
